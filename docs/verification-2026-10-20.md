## Исправлено по результатам

1. Prisma ошибочно считала `prisma/migrations/manual` отдельной миграцией
   и падала с P3015. Копия ручного SQL перенесена в `prisma/manual`.
   Ограничения уже включены в полноценную миграцию constraints.
2. CI теперь проверяет `prisma migrate deploy`, а не заменяет миграции `db push`.
3. Генерация номера заявки гонялась на чтении максимального номера:
   параллельные запросы получали одинаковые номера и ошибку уникальности.
   Добавлена транзакционная advisory-блокировка PostgreSQL на год.
4. Отдельная конфигурация throttler в AuthModule ограничивала профиль
   пятью запросами. Ограничение перенесено на метод входа, остальные
   запросы используют общий лимит.
5. Браузерный тест нового типа проверял исчезновение текста кнопки,
   которое происходит уже во время отправки, и читал заявку до завершения
   согласования. Теперь ожидается ответ POST approve. Для обычного типа
   без выдачи и подписи конечный статус по движку — ISSUED, а не APPROVED.
6. Android: закрыт ошибочно вложенный комментарий в AuthInterceptors,
   добавлены импорты rememberSaveable, исправлена видимость FieldValue.
   Локальный путь SDK обновлён после переноса компьютера.

## Что пока нельзя считать проверенным

Дополнение: debug Android получил редактируемый адрес API на экране входа.
Настоящий телефон использует адрес компьютера в Wi-Fi или localhost с adb reverse,
а не адрес эмулятора 10.0.2.2. При смене адреса старые токены удаляются.
На момент изменения физический телефон к adb не подключён; проверка на устройстве
остаётся обязательной. HTTP разрешён debug-ресурсом, release запрещает cleartext.
Повторный `assembleDebug` после настройки сервера завершился BUILD SUCCESSFUL.

Удалённая учебная PostgreSQL: порт доступен, но попытка защищённого соединения
вернула «server does not support TLS». Соединение без TLS не выполнялось,
структура удалённой схемы ещё не прочитана. Реквизиты хранятся только в
игнорируемом `.env.remote`, основная локальная конфигурация не заменялась.

- iOS: исходников клиента, кроме README, нет; сборка требует macOS/Xcode.
- Нативный Tauri: Rust недоступен в текущем окружении, установщики не собраны.
- PUSH пока заглушка; реальная доставка APNs/FCM не реализована.
- Email не реализован.
- Проверка браузерного React-клиента не заменяет проверку защищённого
  хранилища и системных интеграций внутри Tauri.
- Проверка debug APK не заменяет запуск на Android-устройстве и проверку релизной сборки.
- В Tauri refresh-токен сохраняется обычным plugin-store в `auth.json`.
  Это не Keychain и не зашифрованное хранилище. До выпуска нужно заменить
  его защищённым механизмом и исправить прежние заявления о защищённости.
- Health сейчас проверяет только PostgreSQL, не Redis и MinIO.
- Внешняя доставка PUSH может быть инициирована до фиксации транзакции;
  для настоящего провайдера требуется доставка после commit/outbox.
- При одновременной тяжёлой сборке Android наблюдалось превышение стандартного
  таймаута транзакции Prisma (5 секунд) на подаче заявки. Проверка без нагрузки
  и нагрузочное профилирование остаются отдельными проверками.

## Повторение проверок

Из корня проекта, с заданным `DATABASE_URL` отдельной тестовой базы:

```powershell
pnpm.cmd build
pnpm.cmd lint
pnpm.cmd test
pnpm.cmd --filter @edinoe-okno/api prisma:deploy
pnpm.cmd --filter @edinoe-okno/api test:integration
```

Интеграционные тесты очищают указанную базу. Не направлять их на рабочую БД.

Браузерные проверки требуют запущенных API, Vite, seed и браузера Puppeteer.
Из `apps/api`, при загрузке корневого `.env`:

```powershell
node -r dotenv/config test/e2e/desktop-smoke.cjs dotenv_config_path=../../.env
node -r dotenv/config test/e2e/new-type-flow.cjs dotenv_config_path=../../.env
node -r dotenv/config test/e2e/services-smoke.cjs dotenv_config_path=../../.env
```

Эти сценарии создают данные; использовать выделенную тестовую базу API.

### Android на этой Windows-машине

JDK 21 установлен в `C:\Program Files\Android\openjdk\jdk-21.0.8`.
В игнорируемом `clients/android/local.properties` прописан фактический SDK.
Из `clients/android`:

```powershell
$env:JAVA_HOME='C:\Program Files\Android\openjdk\jdk-21.0.8'
$env:ANDROID_HOME="$env:LOCALAPPDATA\Android\Sdk"
$env:PATH="$env:JAVA_HOME\bin;$env:PATH"
$env:JAVA_TOOL_OPTIONS='-Djdk.net.unixdomain.tmpdir=C:/Windows/Temp'
./gradlew.bat assembleDebug testDebugUnitTest lintDebug '-Pandroid.overridePathCheck=true' --no-daemon --max-workers=1 '-Dorg.gradle.jvmargs=-Xmx1024m -Dfile.encoding=UTF-8'
```

Первая ошибка JDK `Unable to establish loopback connection` обходится коротким
путём временных Unix-сокетов. Проверка не-ASCII пути Android отключена только
для этого запуска. Один worker ограничивает расход памяти при работе Docker.
Собственных Android unit-тестов в `app/src/test` пока нет; задача с NO-SOURCE
не означает успешного прохождения каких-либо тест-кейсов приложения.
