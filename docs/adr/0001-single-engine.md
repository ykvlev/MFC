# ADR 0001: Один движок заявок

## Статус
Принято.

## Контекст
ТЗ раздел 1.1: система — это один движок заявок с конфигурируемыми типами, а не набор
независимых модулей. Добавление нового типа заявки не должно требовать изменения кода
ядра.

## Решение
- Тип заявки (`application_types`) хранит конфигурацию: `fields_schema` (JSONB),
  маршрут (`route_steps`), `access_rule` (JSONB), флаги `uses_cell` / `uses_booking` /
  `requires_signature`, имя PDF-шаблона.
- Ядро (`modules/applications`) не знает про конкретные типы. Оно исполняет статусную
  машину (`ALLOWED_TRANSITIONS` из `packages/shared`), генерирует этапы по маршруту,
  ветвится только по флагам типа.
- Спецмодули (`cells`, `bookings`, `documents`) подключаются через флаги и не имеют
  обратных зависимостей на ядро.

## Последствия
- Новый тип = запись в БД через админку. Проверяется e2e-тестом (ТЗ 15.3, 17).
- Клиенты рендерят форму динамически по `fields_schema` — общая Zod-схема
  (`buildFormSchema`) на бэкенде и десктопе, портированная логика на iOS/Android.
