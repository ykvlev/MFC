# Материалы для защиты

## Анимированная архитектура

Открыть `application-layers.html` двойным щелчком в Chrome или Edge.
Это самостоятельная интерактивная страница: сервер, Docker и интернет не нужны.
Все стили, код анимации и библиотеки встроены в файл. Файл можно перенести на флешку.

Для показа:

1. Открыть страницу и включить полноэкранный режим браузера клавишей F11.
2. Выбрать сценарий и нажать «Запустить».
3. Использовать «Пауза» для пояснений; нажимать на блоки для описания компонента.
4. Если схема не помещается на экране, уменьшить масштаб браузера сочетанием Ctrl−.

Три сценария: заявка и выдача, создание PDF, бронирование места.
Схема объясняет устройство системы; она не подключается к работающему API.
Планы и заглушки помечены отдельно. Снимок архитектуры — 10 сентября 2026.

Это анимация в браузере, не видеофайл для вставки в PowerPoint.

## Ближайшие задачи для демонстрации

1. Пройти цепочку Android → API → интерфейс сотрудника → выдача и статус ISSUED.
2. Проверить ключевой сценарий: администратор создаёт новый тип и маршрут,
   студент видит тип и подаёт заявку без изменения кода.
3. Завершить загрузку файлов на Android; проверить прикрепление, скачивание и PDF.
4. Добавить демо-заявки разных статусов и актуальные периоды бронирования.
5. Пройти сценарий защиты целиком и закрепить его автоматическими e2e-проверками.

Отдельный блокер: нативную сборку Tauri блокирует политика Windows (os error 4551).
Серверные интеграционные тесты пройдены; реальная работа Android с API ещё не проверена.

## Демо-данные (15.09.2026)

На локальной базе созданы заявки 2026-000001…2026-000005 студента
`student1@student.local`: DRAFT, IN_REVIEW, NEEDS_FIX, READY, ISSUED.
Пароль этого учебного пользователя из базового seed — `student12345`.
Будущий «Демо-заезд» доступен для бронирования. Заявки проходят реальные сервисы
с журналом и уведомлениями, а не прямое присваивание статусов.

Добавить отсутствующие демо-данные без сброса базы:

```powershell
. ./scripts/dev-env.ps1
pnpm.cmd --filter @edinoe-okno/api prisma:seed:demo
```

Не повторять базовый seed ради демонстрации: он обновляет конфигурации типов.
Демо-seed оставляет уже существующие заявки как есть, даже если на защите их изменили.
READY-ячейка имеет обычный срок хранения, поэтому перед защитой проверить её состояние.

Проверка входа и восстановления сессии интерфейса (API и Vite должны работать):

```powershell
. ./scripts/dev-env.ps1
node apps/api/test/e2e/desktop-smoke.cjs
```
